# EKS teardown evidence — 2026-08-31

This record closes the first end-to-end KubeVista deployment documented in
[`live-eks-2026-08-31.md`](live-eks-2026-08-31.md). It records the destructive
actions, exceptions, retained artifacts, and final verification. No credentials,
temporary passwords, or authentication tokens are included.

## Scope

- AWS account: `637246456891`
- AWS Region: `us-west-2`
- Environment: `kubevista-dev`
- Public hostname: `kubevista.illuma.me`
- Terraform result: environment state contains zero resources
- Git result: the working tree remained clean throughout teardown

The goal was to remove recurring demo infrastructure while preserving the
encrypted Terraform backend, signed container artifacts, repository history,
and the unrelated `illuma.me` Vercel site.

## Safe destruction sequence

1. Argo CD's application controller was scaled to zero so automated self-heal
   could not recreate public resources during teardown.
2. The `kubevista-web` Ingress was deleted, and the AWS Application Load
   Balancer was observed as deleted before Terraform began removing the VPC.
3. The guarded destroy helper created a saved plan. The reviewed plan contained
   `0 to add, 0 to change, 106 to destroy`; the exact confirmation
   `DESTROY kubevista-dev` was required before applying it.
4. Terraform removed Cognito, the budget, EKS add-ons and Pod Identity
   associations, IAM integrations, the managed node group, NAT gateway,
   Elastic IP, subnets, internet gateway, EKS control plane, security groups,
   logs, and VPC.
5. Route 53 initially rejected hosted-zone deletion because ExternalDNS-created
   A and AAAA aliases were not Terraform resources. Those two aliases were
   inspected and deleted explicitly. A second saved plan contained
   `0 to add, 0 to change, 1 to destroy` and removed only the now-empty hosted
   zone.
6. Five unattached, encrypted gp3 volumes created dynamically by EBS CSI were
   inspected and deleted: Grafana (5 GiB), Alertmanager (5 GiB), Tempo
   (10 GiB), Loki (20 GiB), and Prometheus (20 GiB). Their observability data
   was intentionally ephemeral and is not recoverable.
7. Four `kubevista` NS delegation records were removed from the parent
   `illuma.me` zone in Vercel after the Route 53 zone was gone. Apex, `www`,
   verification, CAA, Vercel ALIAS, and certificate configuration were left
   unchanged.

## Exceptions found during teardown

### ExternalDNS records blocked hosted-zone deletion

Terraform owned the Route 53 zone, certificate-validation record, and CAA
record, while ExternalDNS owned the application aliases. Deleting the zone
before removing controller-created records produced `HostedZoneNotEmpty`.
This is an ownership-boundary issue, not a reason to enable indiscriminate
`force_destroy`: production teardown should inspect and remove controller-owned
records deliberately.

### Dynamically provisioned volumes outlived the cluster

The observability PVCs were not Terraform resources. After EKS deletion, five
volumes were still `available` and unattached, totaling 60 GiB. Each carried
`Project=KubeVista`, `KubernetesCluster=kubevista-dev`, EBS CSI, PV, PVC,
namespace, and workload-specific tags. Direct EC2 inspection established that
they were cluster-owned before deletion.

### AWS tag-index lag caused a false failure

The Resource Groups Tagging API continued to return seven volume ARNs after two
had already disappeared and later continued returning all seven after direct
deletion. Direct `DescribeVolumes` calls reported the authoritative live state.
The cleanup verifier now queries the EC2 volume API directly and validates live
load balancers instead of treating tag-index tombstones as billable resources.

### SSO expired during the final pass

The AWS CLI still had valid short-lived role credentials while Terraform's SDK
attempted to refresh an expired IAM Identity Center token. Reauthentication was
completed in the operator's browser. The already-issued temporary credentials
were exported only into the destroy process environment; they were neither
printed nor stored in the repository.

## Rebuild path

The environment can be recreated from source without recovering the deleted
observability data:

1. authenticate with IAM Identity Center;
2. reuse the retained state backend and ECR repositories;
3. run the guarded Terraform plan/apply workflow;
4. bootstrap Argo CD and the root application;
5. restore the new Route 53 nameserver delegation in the parent DNS zone;
6. validate all eight layers and public delivery using the runbook.

New Route 53 hosted zones receive their own nameserver set. Never restore the
old delegation values from this evidence file.
